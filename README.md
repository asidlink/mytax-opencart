## 🎯 Описание

**«Мой налог: кассовые чеки для ИП (НПД)»** — расширение для OpenCart 4, которое:

1. При оплате заказа автоматически создаёт **чек дохода** в сервисе «Мой налог» (ФНС) через официальное API `https://lknpd.nalog.ru/api/v1`.
2. Генерирует **QR-код чека ФНС** и сохраняет путь к изображению в базе данных.
3. Встраивает **блок чека с QR-кодом** прямо в HTML-письма покупателю:
   - письмо о **новом заказе** (`mail/order_add`);
   - письмо об **изменении статуса** (`mail/order_history`).

Покупатель получает письмо с номером чека, суммой, датой, ссылкой «Открыть чек ФНС» и QR-кодом, который можно отсканировать камерой смартфона для проверки чека в приложении ФНС.

Модуль написан **полностью на PHP** — не требует Node.js и дополнительных composer-пакетов. QR-коды генерируются встроенной библиотекой **phpqrcode** (поставляется вместе с модулем).

> Проект вырос из отдельного **Node.js-сервиса** (v1.x), который создавал чеки через HTTP-API. Начиная с версии **4.0.1** вся логика переписана на PHP и встроена непосредственно в OpenCart 4. Исходный код Node.js-сервиса сохранён в этом репозитории (см. раздел [Состав репозитория](#-состав-репозитория)).

## ✨ Возможности

- ✅ Автоматическое создание чеков в «Мой налог» при оплате заказа
- ✅ Поддержка **ЮKassa** (чек создаётся после подтверждения оплаты)
- ✅ QR-код чека ФНС в письмах покупателю (встроенная библиотека phpqrcode)
- ✅ Retry-механизм при временных ошибках ФНС (до 3 попыток)
- ✅ Логирование всех операций в `storage/logs/mytax.log`
- ✅ Работает на **Windows и Debian/Linux**
- ✅ Не зависает при установке (фикс «Обновить файлы поставщиков»)
- ✅ Защита от дублей писем и повторных чеков
- ✅ 6 событий OpenCart для полного жизненного цикла чека

## 📋 Требования

| Компонент | Требование |
|-----------|------------|
| OpenCart | **4.x** (PHP 8+) |
| PHP | 8.0+ с расширениями `curl`, `gd` (для QR-кодов), `zip` |
| Статус | Активный статус самозанятого (НПД) в «Мой налог» |
| ИНН/пароль | Логин и пароль от ЛК «Мой налог» (https://lknpd.nalog.ru) |

## 🚀 Установка

### Способ 1. Установка модуля через админку OpenCart

1. Скачайте `mytax.ocmod.zip` из [Releases](https://github.com/asidlink/mytax-opencart/releases) (или из каталога `releases/`).
2. Откройте **админку** → **Расширения → Установка расширений**.
3. Загрузите файл `mytax.ocmod.zip` и нажмите «Установить».
4. Если установка зависает на шаге «Обновить файлы поставщиков» — см. [раздел про Debian](#способ-2-автономная-установка-на-debianlinux-рекомендуется).
5. После установки: **Расширения → Модули → Мой налог: кассовые чеки для ИП (НПД)**.
6. Включите модуль, укажите **ИНН** и **пароль** от «Мой налог», нажмите «Сохранить».

### Способ 2. Автономная установка на Debian/Linux (рекомендуется)

> Решает известную проблему зависания установки на шаге «Обновить файлы поставщиков» (из-за большого каталога `storage/vendor`, например SDK ЮKassa).

Скопируйте на сервер:

- `mytax.ocmod.zip`
- `install_mytax_debian.php`

Отредактируйте в `install_mytax_debian.php` блок конфигурации:

```php
$DIR_OPENCART = '/var/www/site/';    // путь к OpenCart
$DIR_STORAGE  = '/var/www/storage/'; // путь к storage
$DB_HOST = 'localhost';
$DB_USER = 'root';
$DB_PASS = '';                        // укажите ваш пароль БД
$DB_NAME = 'metalka';                 // укажите имя вашей БД
$DB_PREFIX = 'oc_';
```

Запустите:

```bash
php install_mytax_debian.php
```

Скрипт:

- распакует модуль в `extension/mytax`;
- создаст таблицу `oc_mytax_receipts`;
- зарегистрирует **6 событий** в `oc_event`;
- добавит записи в `oc_extension_install`, `oc_extension`, `oc_extension_path`;
- включит модуль и сохранит настройки;
- автоматически пропатчит `system/helper/vendor.php` (фикс зависания установки).

### 🖥️ Node.js-сервис (для исторической версии v1.x)

Исходный код Node.js-сервиса сохранён для тех, кто использует старую архитектуру (отдельный процесс создания чеков):

```bash
# 1. Установка зависимостей
npm install

# 2. Конфигурация
cp .env.example .env
#   → укажите ИНН, PASSWORD, APPNAME, API_PASS, PORT

# 3. Запуск
npm start
# или
node server.js
```

HTTP-эндпоинты:

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/health` | Проверка связи с API ФНС |
| POST | `/api/v1/create-receipt` | Создание чека (`{ api_pass, orderId, email, items[] }`) |

Альтернатива без сервера — CLI:

```bash
echo '[{"name":"Товар","price":100,"quantity":1}]' | node mytax-cli.js 81 customer@mail.ru
```

## 🔄 Как это работает

### Жизненный цикл чека

```
Покупатель оплачивает заказ (ЮKassa / другой способ)
        │
        ▼
┌─────────────────────────────────────────────────┐
│ Событие: model/checkout/order.addHistory/before  │
│ Контроллер: orderHistory()                       │
│ → createReceipt(order_id, email, status_id)      │
└─────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────┐
│ Модель: createReceipt()                          │
│ 1. Проверка: модуль включён, статус заказа       │
│ 2. Загрузка товаров заказа                       │
│ 3. Авторизация в API ФНС (ИНН + пароль)          │
│ 4. Отправка чека дохода в ФНС                    │
│ 5. Генерация QR-кода (phpqrcode)                 │
│ 6. Сохранение чека в oc_mytax_receipts           │
└─────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────┐
│ Событие: view/mail/order_add/after               │
│ Контроллер: viewOrderAddAfter()                  │
│ → injectReceiptBlock()                           │
│ Встраивает блок чека с QR в HTML письма          │
└─────────────────────────────────────────────────┘
        │
        ▼
Покупатель получает письмо с QR-кодом чека ФНС ✅
```

### Зарегистрированные события

| Код | Триггер | Действие |
|-----|---------|----------|
| `mytax_order_history` | `catalog/model/checkout/order.addHistory/before` | Создание чека при смене статуса |
| `mytax_mail_order_add` | `catalog/view/mail/order_add/before` | Подготовка данных чека для письма |
| `mytax_mail_order_history` | `catalog/view/mail/order_history/before` | Подготовка данных чека для письма |
| `mytax_mail_order_add_after` | `catalog/view/mail/order_add/after` | **Встраивание QR-блока** в письмо о новом заказе |
| `mytax_mail_order_history_after` | `catalog/view/mail/order_history/after` | **Встраивание QR-блока** в письмо об изменении статуса |
| `mytax_checkout_success` | `catalog/view/checkout/success/before` | Страховка: создание чека на странице успеха |

### Что получает покупатель

В письмо встраивается таблица:

- **Номер чека** (receiptId из ФНС)
- **Сумма** (в рублях)
- **Дата**
- **Ссылка «Открыть чек ФНС»** (printLink)
- **QR-код** 140×140 px → сканируйте камерой смартфона для проверки чека в приложении ФНС

## 🔧 Устранение неполадок

### Письмо пришло без QR-кода

Проверьте:

1. **Лог модуля**: `storage/logs/mytax.log` — ищите строку `Библиотека QR не найдена` или ошибки ФНС.
2. **Расширение GD** установлено в PHP? Проверьте: `php -m | grep gd` (или в админке «Панель состояния»).
3. **Права на запись** в `image/mytax_qr/` — каталог должен быть доступен веб-серверу.
4. **После обновления с 4.0.7 → 4.0.8**: переустановите модуль через админку (или запустите `install_mytax_debian.php`), чтобы зарегистрировались **новые after-события**.

### Установка зависает на «Обновить файлы поставщиков»

Это известная проблема на Debian/Linux с большим каталогом `storage/vendor` (например, SDK ЮKassa с десятками тысяч файлов). Используйте автономную установку:

```bash
php install_mytax_debian.php
```

Скрипт пропатчит `system/helper/vendor.php` — добавит `set_time_limit(600)` и быстрый кэш-выход, после чего установка любого расширения станет мгновенной.

### Чек не создаётся

1. Откройте `storage/logs/mytax.log`.
2. Проверьте статус модуля в админке (включён?).
3. Проверьте корректность ИНН и пароля от «Мой налог».
4. Убедитесь, что сервер имеет **IP РФ** — API ФНС блокирует зарубежные адреса.
