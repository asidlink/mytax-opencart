# 📜 История версий

Все изменения модуля **«Мой налог: кассовые чеки для ИП (НПД)»** с датами.

Формат версий: **4.0.x** (текущая линия OpenCart 4).

## [4.0.8] — 07.08.2026

### ✅ Исправлено: QR-код чека ФНС отсутствовал в письмах покупателю

**Проблема:** покупатель получал письмо о заказе, но без QR-кода чека ФНС.

**Причины (две):**

1. **Библиотека phpqrcode не поставлялась с модулем.** `generateQRCode()` искала библиотеку только по путям разработчика (`C:/sites/metalka/phpqrcode/phpqrcode.php`, `C:/TEST/...`), которых нет на боевом сервере Debian 13. QR-изображение не генерировалось, `qr_code_path` в БД оставался пустым.

2. **Шаблоны писем не выводили чек.** Даже когда чек создавался, `order_add.twig` и `order_history.twig` не содержали блока `mytax_receipt` — данные чека не попадали в письмо.

**Исправления:**

- Встроена самодостаточная библиотека **phpqrcode** в модуль: `catalog/model/checkout/phpqrcode.php` (merged-версия 1.1.4, не требует внешних файлов).
- `generateQRCode()` теперь ищет встроенную библиотеку через `DIR_EXTENSION . 'mytax/catalog/model/checkout/phpqrcode.php'` — корректно работает на Debian/Linux и Windows.
- Добавлены **after-события** `catalog/view/mail/order_add/after` и `catalog/view/mail/order_history/after`:
  - `viewOrderAddAfter()` — встраивает блок чека в письмо о новом заказе;
  - `viewOrderHistoryAfter()` — встраивает блок чека в письмо об изменении статуса;
  - `injectReceiptBlock()` — формирует HTML-таблицу: номер чека, сумма, дата, ссылка «Открыть чек ФНС» и QR-код (140×140 px).
- `getReceiptData()` теперь требует наличие QR-изображения — блок не выводится с пустой картинкой.
- В `install()`/`uninstall()` модели зарегистрированы все **6 событий** (старые 4 + 2 новых after).
- `install_mytax_debian.php` обновлён: регистрирует 6 событий, версия 4.0.8.

**Файлы изменены:**
- `catalog/model/checkout/mytax.php` — исправлен `generateQRCode()`.
- `catalog/model/checkout/phpqrcode.php` — **добавлена** встроенная библиотека QR.
- `catalog/controller/module/mytax.php` — добавлены after-методы + `injectReceiptBlock()`.
- `admin/model/module/mytax.php` — 6 событий.
- `install_mytax_debian.php` — 6 событий, версия 4.0.8.

## [4.0.7] — 06.08.2026

### ✅ Исправлено: чек не создавался при смене статуса заказа

**Проблема:** событие `model/checkout/order.addHistory/before` срабатывает **до** обновления `order_status_id` в БД — модуль видел старый (нулевой) статус и отказывался создавать чек («Заказ не оплачен»).

**Исправления:**

- `createReceipt()` принимает `order_status_id` из аргументов события (актуальный новый статус) вместо статуса из БД.
- `viewOrderAdd()` и `viewOrderHistory()` передают `force=true` при рендере письма — чек гарантированно создаётся перед отправкой, так как письмо отправляется только при положительном статусе.
- Исправлено бесконечное кручение при установке: добавлен `description` в `addEvent()`.
- Устранён синтаксис `??` внутри строковой интерполяции в каталог-модели.

## [4.0.4] — 03.08.2026

### 🚀 Фикс «Обновить файлы поставщиков» (Debian)

**Проблема:** на Debian/Linux установка любого расширения зависала на шаге «Обновить файлы поставщиков» из-за огромного каталога `storage/vendor` (SDK ЮKassa — десятки тысяч файлов).

**Исправления:**

- Добавлена OCMOD-модификация `mytax_fix_vendor_hang.ocmod.xml`:
  - `set_time_limit(600)` в `oc_generate_vendor()`;
  - быстрый кэш-выход, если `vendor.php` уже сгенерирован и `composer.json` не менялись.
- Создан автономный установщик `install_mytax_debian.php` для установки без шага vendor.

## [4.0.1] — 31.07.2026

### 🎉 Первый релиз PHP-версии (полная переработка)

**Проблема:** предыдущая версия модуля использовала внешний Node.js-сервис (`fns-receipt-service`), что усложняло установку и требовало отдельного процесса.

**Исправления:**

- Модуль переписан **полностью на PHP** (без Node.js).
- Прямая работа с API ФНС: `https://lknpd.nalog.ru/api/v1/auth/lkfl`, `/income`.
- Чек создаётся после успешной оплаты.
- Письмо дополняется QR-кодом (не блокируется).
- Логирование в `storage/logs/mytax.log`.
- Корректная установка через `install.php` → `install()`.

## [1.x] — 2025 (Node.js сервис)

Предыдущая реализация — отдельный Node.js-сервис `fns-receipt-service`:
- HTTP-API для создания чеков;
- отправка детализированных HTML-чеков клиентам по email;
- гибридный подход: в ФНС — агрегированная позиция, клиенту — детализация.

> Заменён PHP-версией 4.0.1+ для встраивания непосредственно в OpenCart 4.
